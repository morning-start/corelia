## 一、项目概述

### 1.1 项目定位

Corelia 是一个基于 **Tauri 2.x + Svelte 5 + Rust** 的 Windows 桌面快速启动器，对标 uTools / Listary / Flow Launcher 等效率工具。核心架构采用 QuickJS + WASM 双引擎插件系统，是国内首个深度兼容 uTools API 的开源替代方案。

### 1.2 技术栈

| 层级 | 技术 | 版本 |
|------|------|------|
| 桌面框架 | Tauri | 2.x |
| 前端框架 | SvelteKit + Svelte 5 Runes | 2.x + 5.x |
| 前端语言 | TypeScript | ~5.6.2 |
| 构建工具 | Vite | 6.x |
| 包管理器 | Bun | 1.3+ |
| 后端语言 | Rust | 1.94.0 |
| 插件引擎 | QuickJS (rquickjs) | 0.11.0 |
| WASM 扩展 | wasm-pack + wasm-bindgen | latest |

### 1.3 当前阶段

MVP 核心框架阶段，插件系统端到端闭环已打通：
- ✅ QuickJS VM 池化管理
- ✅ API Bridge 核心注入（storage / clipboard / shell / fetch / fs / dialog）
- ✅ WASM Bridge IPC 通信链路
- ✅ crypto WASM Patch 构建集成
- 🔧 插件状态机鲁棒性强化（进行中）
- 🔧 样例插件开发（进行中）

## 三、架构对比分析

### 3.1 插件执行引擎对比

```
                    Flow Launcher (进程隔离)
                    ┌─────────────────────────┐
                    │  每个插件 = 独立进程       │
                    │  JSON-RPC 2.0 通信        │
                    │  启动: 数百ms              │
                    │  内存: ~15MB / 进程        │
                    └─────────────────────────┘

                    Corelia (QuickJS VM 池)
                    ┌─────────────────────────┐
                    │  预创建 VM 池，按需复用     │
         ┌─────────►│  rquickjs API Bridge      │
         │          │  启动: ~300µs (VM 复用)     │
┌────────┴──────┐   │  内存: ~2MB / VM          │
│ 主进程 Rust   │   └─────────────────────────┘
│ (Tauri Core)  │
└────────┬──────┘   ┌─────────────────────────┐
         │          │  WASM Patch 扩展 (独有)   │
         └─────────►│  高性能计算任务卸载         │
                    │  任意语言 → WASM           │
                    │  字节码级沙箱安全           │
                    └─────────────────────────┘
```

### 3.2 技术选型合理性评估

| 选型 | 替代方案 | 选择理由 | 评估 |
|------|---------|----------|:--:|
| **QuickJS (rquickjs)** | V8 (deno_core) / Node.js | 体积小 (210KB)、启动极快、沙箱天然隔离 | 🟢 |
| **WASM Patch** | 原生 DLL / FFI | 跨平台、内存安全、与 QuickJS 互补 | 🟢 |
| **Svelte 5** | React / Vue | 编译时优化、运行时零开销、体积最小 | 🟢 |
| **Tauri 2.x** | Electron | 体积小 10 倍、内存省 5 倍、Rust 安全 | 🟢 |
| **Bun** | npm / pnpm | 安装速度快 10-30 倍 | 🟢 |
| **uTools API 兼容** | 自研 API | 降低插件迁移成本、继承生态 | 🟢 |

## 四、差异化优势分析

### 4.1 Corelia 的 "不可能三角" 解法

```
              QuickJS 轻量沙箱
                  /\
                 /  \
                /    \
               /  唯一 \
              /  组合   \
             /__________\
  uTools API 兼容 ───────── WASM 高性能扩展
```

在 Windows 启动器赛道中，同时具备这三者能力的项目为 **零**。

### 4.2 四大核心优势

| # | 优势 | 竞品覆盖情况 |
|:--:|------|:--:|
| ❶ | **QuickJS + WASM 双引擎** — JS 插件 + 高性能 WASM 计算 | 无人覆盖 |
| ❷ | **uTools API 兼容** — 现有 uTools 插件可迁移 | 无人覆盖 |
| ❸ | **VM 池化管理** — 复用实例，300µs 启动，2MB 内存 | Flow 进程隔离做不到 |
| ❹ | **编译时优化** — Svelte 5 Runes 编译为最小 JS，零运行时 | ZeroLaunch 用 Vue 做不到 |

### 4.3 与领先者的 "错位竞争" 策略

```
Flow Launcher (14.7k⭐)      Corelia (MVP)
─────────────────────        ─────────────
优势:                       优势:
  ✅ 社区生态成熟               ✅ 架构更先进（轻量 10 倍）
  ✅ 插件市场运作多年            ✅ uTools 兼容（迁移捷径）
  ✅ 多语言插件支持              ✅ WASM 扩展（能力上限更高）
                              ✅ 内存/启动完胜
                              
策略: 不正面竞争，走差异化路线
  → 吸引 uTools 用户迁移
  → 用 JS 插件 + WASM 高性能吸引开发者
  → 轻量架构作为核心卖点
```

## 六、风险评估

### 6.1 技术风险

| 风险 | 等级 | 描述 | 缓解措施 |
|------|:--:|------|------|
| QuickJS ES2024 特性缺失 | 🟢 低 | ES2023 已覆盖 99% 场景 | 跟随 QuickJS 版本升级 |
| WASM 编译环境差异 | 🟡 中 | wasm-pack 工具链在不同环境表现不一致 | CI 统一环境 + 预编译 artifacts |
| VM 池并发安全 | 🟡 中 | 多 VM 同时操作共享资源需要 Rust 锁机制 | Arc\<Mutex\> 保护共享状态 |
| Tauri 2.x 升级不兼容 | 🟢 低 | 主版本升级可能引入 breaking changes | 锁定版本，延迟大版本升级 |

### 6.2 产品风险

| 风险 | 等级 | 描述 | 缓解措施 |
|------|:--:|------|------|
| 社区冷启动 | 🟡 中 | 开源项目从零积累用户 | uTools 迁移策略 + 开发者口碑 |
| uTools API 不兼容 | 🟡 中 | 无公开规范，靠逆向和推断 | 渐进兼容，先覆盖高频 API |
| 开发者门槛 | 🟡 中 | Rust + WASM 组合学习成本高 | 简化 JS 插件开发体验 |
| Flow Launcher 压制 | 🟢 低 | 技术栈不同，定位不同 | 差异化竞争，不正面冲突 |

### 6.3 市场风险

| 风险 | 等级 | 描述 | 缓解措施 |
|------|:--:|------|------|
| Windows 11 自带改进 | 🟢 低 | 微软持续改进搜索体验 | 插件生态系统是护城河 |
| AI 原生启动器出现 | 🟡 中 | ChatGPT-like 界面可能取代传统搜索 | 预留 AI 语义搜索接口 |

## 八、结论与建议

### 8.1 总体结论

```
技术可行  |  ██████████  🟢 90%
市场时机  |  ████████    🟢 80%
竞争差异  |  █████████   🟢 85%
风险可控  |  ███████     🟡 70%
─────────────────────────────────
综合评估  |  ████████    🟢 81%
```

**核心判断**: Corelia 的架构设计合理，选择了正确的技术路径。QuickJS + WASM 双引擎 + uTools API 兼容构成了不可替代的竞争壁垒。Flow Launcher 的 14.7k stars 验证了赛道需求，Corelia 有机会通过更先进的技术架构切入市场。

### 8.2 建议

1. **焦点策略**: MVP 阶段只做插件系统的端到端闭环，不扩展功能边界
2. **先验证再扩展**: 等 uTools API 兼容度达到可用标准再进入 Alpha
3. **开发者优先**: Beta 阶段重心放在降低开发者门槛（文档、脚手架、调试工具）
4. **借势 uTools**: 发布时提供 uTools → Corelia 迁移工具，利用现有生态
5. **保留 AI 接口**: 架构上预留 AI 语义搜索接口，应对未来竞争
